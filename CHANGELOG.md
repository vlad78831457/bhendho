# Журнал изменений

Каждая ветка дописывает строку в «Не выпущено». Ветка указана в скобках.

## Не выпущено

- ядро перенесено из `taleweaver-app-vr-ab` (main `0912a91`): ядро платформы v0.1.0 + промокоды, OAuth, кабинет, файлы; контракты; Python SDK; спецификация и история решений ADR-01…60 (`task/ab-core`).
- роли пользователя `user`, `tester`, `admin`: поле в базе, видно в профиле, меняется только командой `core user-role` на сервере (ADR-61) (`task/ac-roles`).
- зачисление по метке «Пополнить»: `POST /api/v1/topup-marks` выдаёт одноразовую метку, вебхук службы оплаты гасит код по `user_mark` вместо email; контракт эмитента дополнен (ADR-62) (`task/ad-topup-mark`).
- списание сверх резерва до `резерв × CORE_OVERDRAFT_FACTOR` (1.5), запись журнала `overcharge`, минус на кошельке, в минусе задачи не создаются (ADR-63) (`task/ae-overdraft`).
- фронт движка в `web/`: фронт по бланкам из `taleweaver-app-vr-ab` без экрана сказки, адрес `/admin/`, только для роли `admin`; `make test` гоняет `tsc` и `vitest` (ADR-64) (`task/af-web`).
- ADR-61…64 и строки журнала — по порядку номеров после слияний (`task/ag-adr-order`).
- факты подразделений: `audience` у формы в паспорте, `report.service_facts` в отчёте прораба, таблица `service_facts` с семью полями ядра и составным индексом, вырезаются из отчёта пользователя; SDK — `ctx.remember()` (ADR-65) (`task/ah-service-facts`).
- простая панель админа во фронте ядра: «Подразделения» (бланки с «кому» и полями), память подразделения по бланку (последние 100, запись факта формой бланка), «Настройки» только для чтения (`task/aj-admin-panel`).
- API панели админа: подразделения и бланки, последние 100 фактов подразделения, факт от админа (`writer` = `admin:<id>`), настройки без секретов; только роль `admin` (ADR-66) (`task/ai-admin-api`).
- выгрузка всей базы за период: `GET /api/v1/admin/export` — ZIP по таблицам в JSON Lines, без секретов, только роль `admin`; форма в панели (ADR-67) (`task/ak-export`).
- пометки пользователя в бланк: форма задачи просит `user_marks: [role]`, ядро кладёт их в снимок для прораба; SDK — `ctx.user_marks` (ADR-68) (`task/al-user-marks`).
- тарифы в панели: цена бланка, курсы единиц, множитель минуса — журнал `tariff_changes`, без перезапуска, задача помнит тарифы на момент создания; экран «Тарифы» (ADR-69) (`task/am-tariffs`).
- подразделение подключается само: ключ от админа, `POST /gateway/v1/register` с паспортом и формами без перезапуска ядра, ключ — токен прораба, выключатель подразделения; SDK — `client.register()` (ADR-70) (`task/an-self-register`).
- заготовка подразделения `templates/department/`: паспорт, бланки (факт, задача, память), прораб на SDK с подключением по ключу, `CLAUDE.md` для агента, `make check` правилами ядра; команда `core check-module`; заготовка проверяется в `make test` (ADR-71) (`task/ao-department-template`).
- разметка общей территории фронта: `views:` в паспорте (card, section, menu; шесть элементов карточки; значки из общего набора), проверка ссылок, `GET /api/v1/views`; SDK фронта `pkg/sdk/ts` рисует её на чистом DOM (ADR-72) (`task/ap-views`).
- поделиться фактом: ссылка на версию без входа (только чтение, отзывается, не для поисковиков, файлы по подписанным ссылкам) и копия к себе без чужих файлов (ADR-73) (`task/aq-share`).
- витрина: админ кладёт свои опубликованные факты с языком и порядком, `GET /api/v1/showcase?lang=` открыт и падает на язык по умолчанию; экран «Витрина» в панели (ADR-74) (`task/ar-showcase`).
- метка источника пользователя: `source` при регистрации или один раз после входа, в ответе погашения кода (`user_source`) и пометкой для прораба (ADR-75) (`task/as-source`).
- уровни прорабов: приоритет прораба на бланк задаёт админ (0 — не берёт), задачу берёт действующий прораб с наибольшим приоритетом; таблица в панели (ADR-76) (`task/at-prorab-priority`).
- прораб сообщает о себе при подключении (название, описание), время последней связи, список выданных ключей с отметкой «подключён»; всё видно в панели (ADR-77) (`task/au-prorab-info`).
- исправления по разбору кода (план 6.1): бланк не перехватить чужим подразделением; факты подразделения и факт-результат — всё или ничего; молчащий старший прораб не держит очередь; сбой базы у админа — 500, не 403; метка источника не ломает регистрацию; старые метки «Пополнить» чистятся; фронт: таблица из одних разделителей не роняет отчёт, без сети сессия не закрывается (`task/av-review-fixes`).
