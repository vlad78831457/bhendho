# Подразделение на ядре OFFGRID — инструкция для агента

Ты пишешь подразделение: прораба и его воркеров. Ядро (`bhendho`) не трогаешь — говоришь с ним только
через контракты.

## Что где

| Файл | Что |
|---|---|
| `module/module.yaml` | паспорт: код подразделения (`worker.target_service`), бланки, единицы учёта |
| `module/forms/*.json` | бланки: `title`, `fields_rules` — словарь типов ядра (ADR-35) |
| `worker/src/department/main.py` | прораб: подключение по ключу и обработчик задачи |
| `worker/tests/` | тесты обработчика без ядра |

## Правила ядра, которые нельзя нарушать

- Ядро не знает предметной области: смысл — только у тебя (ADR-49).
- Бланк `kind: fact` с `audience: user` — факт человека; `audience` любое другое слово — память подразделения,
  пользователь её не видит (ADR-65). Пиши её через `ctx.remember(form_id, values)`.
- Задача получает резерв в GC; плати по факту: `ctx.charge(unit, n)` в единицах паспорта (ADR-47).
- Как показать факты в кабинете и меню — разметка `views:` в паспорте: `card` из шести элементов (`title`, `text`,
  `image`, `facts`, `badge`, `action`), `section`, `menu` со значком из общего набора. Код вида не пиши,
  стили не задавай — рисует оболочка (ADR-72).
- Нужна роль пользователя — попроси её в бланке: `user_marks: [role]`, читай `ctx.user_marks` (ADR-68).
- Подключение: ключ подразделения выдаёт админ в панели; прораб при старте шлёт паспорт и формы
  (`client.register`), потом тем же ключом берёт задачи (ADR-70).
- Секреты — только из переменных окружения (`DEPARTMENT_KEY`, ключи моделей). В файлы не пиши.

## Как проверять

```
make check   # паспорт и формы — теми же правилами, что при регистрации в ядре
make test    # check + ruff, mypy, pytest прораба
```

Работа готова, когда `make test` зелёный. Всё запускается только в Docker.
