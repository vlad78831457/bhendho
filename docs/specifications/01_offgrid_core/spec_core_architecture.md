# Спецификация Архитектурного Ядра OFFGRID (r-aaa-core-a)

## 1. Миссия и назначение
Архитектурное ядро `r-aaa-core-a` реализует отказоустойчивую платформу для долгих асинхронных AI/Compute-задач с мобильных клиентов в условиях нестабильной связи, честным биллингом и модульной структурой.

## 2. Ключевые архитектурные решения (ADR Mapping)
- **ADR-10, ADR-41 (BlankEnvelope):** Единый формат контракта любого документа (`system`, `meta_ui`, `commands`, `values`, `report`).
- **ADR-12 (Потоки):** Шаблоны форм отдаются клиентам только read-only (вниз). Клиент отправляет наверх только `form_id + values + idempotency_key`. Цену и валидацию назначает исключительно сервер.
- **ADR-13, ADR-14, ADR-15 (Факты vs Задачи):**
  - `facts`: сущности реального мира (партии товаров, профили детей, персонажи).
  - `system_tasks`: распоряжения на вычисления (содержат только `fact_ref`).
  - `Materializer`: собирает полный самодостаточный снимок данных для воркера перед вызовом. Воркер изолирован от базы фактов.
- **ADR-08, ADR-18, ADR-30 (Очередь и Прораб):**
  - Захват задач через `FOR UPDATE SKIP LOCKED`.
  - Прораб оценивает время задачи (ETA), ядро устанавливает `locked_until = now() + 3 * ETA`.
  - Попытки воркера (до 5 раз) бесплатны для пользователя.
- **ADR-06, ADR-29 (Финансовый контур и Биллинг):**
  - Деньги меняются только через транзакционные RPC Postgres.
  - При создании задачи сумма резервируется (`reserve`).
  - Воркер отчитывается в собственных единицах (`worker_accounting`), системный бухгалтер пересчитывает их по курсу: `charge = min(факт, резерв)`.
- **ADR-05, ADR-23 (Transactional Outbox & Realtime):**
  - Промежуточный прогресс летит в сокет мимо БД.
  - Финальные статусы пишутся в `outbox_queue` в одной транзакции с задачей.
  - Каждое событие имеет монотонный `seq` для дедупликации на клиенте.
