# Стандарт Подключаемого Модуля OFFGRID (Plugin Standard)

## 1. Структура модуля
Любой модуль для `r-aaa-core-a` поставляется как самостоятельный пакет следующей структуры:
```text
my_module/
├── module.yaml               # Паспорт манифеста (валидируется module_schema.json)
├── forms/                    # JSON-схемы бланков, регистрируемых в ядре
│   ├── fact_entity.json
│   └── task_action.json
├── src/                      # Исходный код (чистый Python)
│   ├── module.py             # Класс реализации IModule
│   └── worker.py             # Логика обработки и вычислений
└── tests/
```

## 2. Жизненный цикл плагина
Плагин обязан реализовывать протокол `IModule` (`contracts/interfaces/base.py`):
1. **`init(context)`**: ядро передает конфигурацию, доступ к `IEventBus` и параметры окружения.
2. **`start()`**: модуль запускает внутренних слушателей или подключается к сторонним сервисам.
3. **`process(blank)`**: атомарная чистая трансформация бланка. Бланк иммутабелен: мутация на месте запрещена, возвращается обновленный экземпляр конверта.
4. **`health()`**: возврат статуса здоровья для мониторинга ядра.
5. **`stop()`**: безопасная остановка (graceful shutdown).

## 3. Отчетность и Биллинг воркера
В ответе на выполнение задачи модуль заполняет секцию `report.worker_charge`:
- `unit_name`: название единицы (например, `llm_tokens`, `gpu_seconds`, `compute_steps`).
- `units_consumed`: количество фактически израсходованных единиц.
Системный бухгалтер ядра автоматически пересчитывает их по курсу из манифеста в GC.
